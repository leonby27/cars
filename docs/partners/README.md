# Кабинет партнёра

Адрес: `/partner`. Ссылки «Вход для партнёров» находятся в меню и подвале сайта.
Ссылка «Зарегистрироваться» на странице входа открывает форму заявки: имя
и телефон. Заявки сохраняются отдельно и видны владельцу в аналитике
→ «Заявки на партнёрство». Повторная отправка с тем же номером обновляет заявку.
Автоматической выдачи доступа нет: владелец по-прежнему создаёт логин и пароль
вручную. Учётные записи партнёров независимы от клиентских
аккаунтов и доступа к аналитике; логин `admin` здесь не даёт прав владельца сайта.

## Выдать доступ

В аналитике откройте «Заявки» → «Доступ для партнёров». Укажите название,
уникальный логин (3–64 латинских символа, цифры, точка, дефис или подчёркивание)
и пароль от 8 символов. Передайте выбранные данные партнёру лично.
Пароль после создания не показывается и не хранится открытым текстом.

Для создания или перевыдачи доступа с сервера есть команда:

```sh
read -rs -p 'Новый пароль: ' partner_password; echo
printf '%s' "$partner_password" | node scripts/provision-partner.mjs partner1 'Название партнёра'
unset partner_password
```

Перевыдача через эту команду обновляет пароль и отзывает старые сессии.
Отключить аккаунт можно в базе: `UPDATE partner_accounts SET active=false WHERE login='partner1';`
Отключение сразу блокирует все его сессии, включая ранее открытый кабинет.

## Передать заявку

В карточке заявки аналитики раскройте «Передать партнёру». Выберите партнёра,
напишите задачу и подтвердите передачу. Передаются только выбранная заявка,
контакты этого клиента, автомобиль и пожелания. Паспортные поля и общий список
клиентов не передаются. Назначение выполняется только вручную.

Повторная передача тому же партнёру обновляет задачу, сохраняя его статус и ответ.
Передача другому партнёру снимает доступ у предыдущего и начинает работу заново.
«Без партнёра» → «Снять назначение» убирает заявку из кабинета.

## Работа партнёра

В кабинете есть обзор, поиск и фильтр заявок, статусы и комментарий для команды.
Открыть подробности → выбрать статус → написать результат → «Сохранить».
В аналитике ответ отображается в том же блоке передачи заявки; «Обновить» получает
актуальные ответы. Автоматические уведомления партнёрам пока не отправляются.
Выплаты, комиссии и финансовый учёт не добавлены: условия ещё не согласованы.

## Локальная подготовка

Миграция `049_partner_portal.sql` создаёт аккаунты, сессии и переданные заявки.
Миграция `050_partner_registration_requests.sql` хранит заявки на участие в программе.
Первоначальный аккаунт создан только в локальной базе; пароль не входит в Git
или браузерную сборку. При публикации его нужно создать на сервере отдельно.
Опция `--demo` у команды создаёт две явно подписанные демонстрационные заявки
только в локальной Docker-базе (localhost/127.0.0.1, порт 54329). На сервере она
запрещена. Демонстрационные заявки не создают клиентов, лидов или уведомлений.

По запросу владельца от 08.10.2026 две демонстрационные карточки в локальном
кабинете заменены копиями трёх последних реальных заявок с фотографиями
автомобилей и контактами. Эти снимки хранятся только в локальной базе под ключами
`local-partner-preview-*`, не входят в Git и не передают заявки партнёру на сервере.

Сессия живёт 7 дней; в базе хранится только хеш её случайного токена. Кука
HttpOnly/SameSite=Strict, Secure на HTTPS. Все изменения проверяют Origin.
Вход ограничен по адресу и логину. Чтение и изменение заявок ограничено
partner_id из действующей сессии; партнёр не может назначать заявки или создавать
аккаунты. Страницы кабинета закрыты от индексации и внешних счётчиков.

Заявки на регистрацию отображаются отдельно в аналитике: «Заявки на партнёрство». Жёлтый квадрат в меню показывает количество непросмотренных заявок и обновляется вместе со срезом аналитики. Открытие этого раздела отмечает только загруженные версии заявок; повторная отправка формы снова делает заявку новой. Отметка хранится на сервере, поэтому действует на всех устройствах. Перед выпуском применить миграцию `051_partner_registration_seen.sql`.
