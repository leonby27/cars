# Почему дешёвые Volvo XC60 недоступны — дополнительная проверка 19 ноября

Проверена вся первая группа из **21 XC60 дешевле 80 000 BYN** при сортировке
по возрастанию цены. Во время открытия каталога цены отображались в BYN;
дальнейшее переключение общей валюты не меняло выбранные ID. На каждой из
21 публичных страниц Che168 19 ноября в 14:06–14:07 по Минску подтверждены
видимый заголовок продажи и пояснение о проданном автомобиле.

Полный список ID, показанные цены, прежние котировки из отчёта и наблюдения:

Это наблюдения публичных страниц, не выгрузка текущего статуса из БД.

В отчёте обычных XC60 с изменением цены всего 47; 21 из них переведена на

Фактические даты продажи неизвестны.

## Почему недоступные машины заняли начало выдачи

До сбоя цены этих машин были разными. После ошибочной актуализации их китайская
цена стала одной и той же — $9 000. Доставка, пошлина и остальные составляющие
остались разными, поэтому итоговый ряд выглядит как несколько разных выгодных
предложений. Сортировка закономерно подняла их выше настоящих котировок.
Следовательно, пользовательская выборка дешёвых машин оказалась почти целиком
выборкой записей сбоя. Это не доказательство, что все эти машины продались сегодня.

## Почему первоначальной правки было недостаточно

1. На реальной странице присутствуют скрытая SSR-копия, настольная и мобильная
   копии одного сообщения о продаже. Текстовый locator без фильтра видимости
   неоднозначен. Он мог переводить подтверждённую продажу в unknown. После
   предыдущего изменения такая машина скрылась бы, но надёжного распознавания
   продажи ещё не было. Исправлено: только видимые совпадения, затем первое
   совпадение; готовность активной и проданной страницы ожидается отдельно.
2. Цены из списков проходили коротким путём: скрытая машина могла снова стать
   активной по списку, без своей карточки. Исправлено: skipped/quarantine требуют
   проверки своей страницы; изменение цены от 30% тоже требует такой проверки.
   30% — повод получить более сильное подтверждение, не критерий ложной цены.
3. Совпадающие ID и положительная цена в RSC сами по себе не исключают старую
   котировку проданного автомобиля. Для индивидуальных проверок и новых импортов
   основного кругового сборщика теперь требуется публичная страница. Явная продажа
   имеет приоритет над сохранённой ценой; неподтверждённая страница скрывает запись.
4. Сбой уже сдвинул `last_checked_at`. Обычное продолжение старого круга могло
   вообще не дойти до испорченных строк. Добавлен режим `--verify-all-details=true`:
   в НОВОМ круге он отключает списочные подтверждения для всего снимка.

Уточнение области изменений: дополнительная публичная проверка новых импортов
подключена к основному `refresh-che168.mjs`. Два отдельных ручных импортёра имеют
проверку ID из предыдущего изменения; этот follow-up не запускал их в интернете
и не подтверждает их работоспособность на сервере.

## Исправит ли обновлённая правка эту ситуацию

Для проверенной группы причина и требуемый результат теперь определены: все
21 должны уйти из активной выдачи. Регрессионный сценарий воспроизводит
пустую карточку с рекомендациями и три копии сообщений о продаже; новый
принудительный круг признаёт 21 продажу и не принимает ни одной цены из рекомендаций.
Это тест разборщика/оркестратора на моделируемом интерфейсе, не живой запуск сборщика.

После доработки: 352 теста по парсерам, циклам, ограничениям каталога и заявкам
прошли; 0 ошибок; 1 тест реальной PostgreSQL пропущен. Тест реального HTTP 407
с локальным сокетом исключён из-за запрета среды. Синтаксис обновляющего скрипта
и `git diff --check` также проверены. Счётчики не суммируются с предыдущими прогонами.

Одной установки кода недостаточно. Нужны скрытие не подтверждённых заново
записей инцидента и запуск после разрешённой установки:

```sh
npm run refresh -- --new-circle=true --verify-all-details=true
```

Остальные ограничения полноты и доступа сохраняются. Публичные проверки
увеличивают число запросов; они учитываются в счётчиках сессии/подхода, а их
количество выводится отдельно. Продолжительность нового режима на сервере
не измерена. Нельзя использовать `--skip-detail` с этим режимом.

Рабочие объявления и службы в этой сессии не изменялись. SSH повторно проверен:
доступ к порту 22 запрещён средой. Исправления остаются локальными, без коммита,
push и публикации. Недельное расписание также не менялось; оно по-прежнему
оставляет окно между реальной продажей и следующим обходом.
