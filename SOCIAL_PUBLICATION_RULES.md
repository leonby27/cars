# Правила подготовки и публикации в соцсетях

Живой документ: сюда записываем принятые правила работы очереди публикаций.
Последнее обновление — 20.09.2026.

Темы, рубрики, приоритетные модели и оформление описаны отдельно в
[`SOCIAL_PLAN.md`](./SOCIAL_PLAN.md). Этот файл отвечает за актуальность,
подготовку запаса, проверку и выпуск готовых публикаций.

## Основной принцип

Изображения можно генерировать заранее без API генератора, используя Codex и
текущую подписку. Но сведения о конкретной машине нельзя считать актуальными до
самого выхода записи: наличие, цена и положение машины в подборке меняются.

Поэтому раз в неделю собираем свежий комплект исходников, затем по расписанию
генерируем варианты по утверждённым промптам и распределяем готовый недельный
комплект по дням публикации.

Небольшое изменение цены или частичная потеря актуальности за несколько дней
допустимы и сами по себе не отменяют публикацию. Запись останавливается только при
существенной проблеме: машина исчезла, ссылка или фотография не работают либо
главное утверждение стало явно неверным.

## На какой срок готовим запас

- **Конкретная машина с ценой и номером** — не более чем на 7 дней вперёд.
- **Самая дешёвая / оптимальная / вопрос о цене** — не более чем на 7 дней и с
  повторной проверкой самого правила отбора перед выходом.
- **Новинки каталога** — собираются после обновления каталога и публикуются в
  ближайшие дни; заранее на месяц не готовятся.
- **Упавшие цены** — собираются только после завершения сравниваемой недели.
- **Подборки по бюджету** — готовятся на неделю и пересчитываются перед выходом.
- **Сравнение моделей без привязки к объявлениям** — можно готовить на месяц.
- **Материалы журнала и объясняющие записи** — можно готовить на месяц и дольше,
  если в них нет текущего курса, квоты, наличия или конкретных цен.

Рабочий режим: один комплект карточек на следующую неделю без резервных карточек.
Месячный запас состоит только из материалов, которые не зависят от конкретного
объявления.

## Почему нужна проверка

По доступной истории каталога примерно 7–8% карточек уже через неделю могут
исчезнуть или изменить цену. К третьей неделе риск доходит примерно до четверти.
Для месяца рабочая оценка риска — 25–40% и выше. Это ориентир по накопленной
истории, а не гарантированная постоянная величина.

Даже если цена продавца не изменилась, итоговая цена до Минска может поменяться
из-за курса и параметров расчёта.

## Еженедельный цикл

1. Система выбирает материалы и машины на следующую неделю из свежего каталога.
2. Для каждой будущей публикации собирается готовая карточка **«Исходник»**: фото,
   заголовок, переносы, фирменное оформление и остальные исходные данные.
3. Каждому исходнику автоматически назначается один из трёх готовых промптов:
   промпт №1 — 50% карточек, промпты №2 и №3 — по 25%.
4. Не реже одного раза в неделю автоматическая задача Codex запускает генерацию
   каждой карточки по назначенному промпту.
5. Для каждой карточки сохраняются исходник, результат генерации и номер
   использованного промпта.
6. В течение следующей недели сгенерированные карточки без ручного утверждения
   выходят по расписанию одновременно в Instagram, Threads и телеграм-канале.

Материал журнала с готовой выжимкой занимает визуальный слот своего буднего дня и
проходит тот же путь через исходник, назначенный промпт и генерацию. Он не добавляет
шестую публикацию. Если выжимки или обложки ещё нет, слот сохраняет назначенную
автомобильную рубрику.

Расписание Codex должно работать с локальным проектом, потому что исходники,
результаты генерации и очередь публикаций находятся в нём. Для планового запуска
компьютер должен быть включён, а настольное приложение Codex — запущено.
Проверка запускается ежедневно в 09:00 по Минску, но создаёт только один пакет на
неделю. Такой режим догоняет пропущенный понедельник после включения компьютера и
повторяет только недостающие генерации; в воскресенье уже готовится следующая неделя.

## Стартовая частота публикаций

- **Пять общих визуальных публикаций в неделю**: одна карточка в день с
  понедельника по пятницу одновременно в Instagram, Threads и телеграм-канале.
- Материалы журнала, подборки, новинки и остальные рубрики входят в эти пять
  публикаций, а не добавляются сверху.
- **Два поста в неделю выходят только в Threads** из отдельного файла с
  готовыми материалами [`../threads.txt`](../threads.txt). В нём сейчас 80
  пронумерованных постов-вопросов. Публикуем их без повторов, сохраняя номер
  последней использованной строки; при темпе два поста в неделю этого хватит на
  40 недель.
- Итого стартовый ритм Threads — семь публикаций в неделю: пять общих карточек и
  два поста из отдельного файла.
- Два текстовых поста Threads никогда не публикуются подряд: они встраиваются по
  времени между визуальными карточками. Если предыдущая фактически вышедшая запись
  Threads была текстовой, следующая текстовая ждёт успешной публикации с картинкой.
- В Instagram и Telegram на старте остаётся по пять публикаций в неделю.
- После первых четырёх полных недель сравниваем охват и реакции на одну публикацию,
  переходы в каталог и рост аудитории. После этого частоту можно повысить или
  снизить на основании собственных данных.

Пять общих карточек — исходная рабочая частота, а не вечное ограничение. Она
попадает в наиболее устойчивый диапазон для Instagram, не перегружает
телеграм-канал и оставляет Threads пространство для более естественных текстовых
публикаций.

## Серия фотографий

- Большинство рубрик публикуется не одной картинкой, а серией фотографий.
- **Стилизуется и проходит генерацию только первая, лицевая карточка серии.**
- У всех пяти публикаций одной недели должны быть разные автомобили на лицевой
  карточке. Машина может повторяться внутри подборки или галереи, но не может стать
  обложкой второго поста той же недели.
- Для подборки лицевая машина выбирается из её участников с учётом уже занятых
  обложек. Если уникальный автомобиль подобрать нельзя, пакет не выпускается.
- Текст лицевой карточки отражает смысл публикации. Для одиночной записи это могут
  быть модель и её фактическая цена; для подборки — тема всей подборки, например
  `5 машин до 25 000 $`. Автомобиль на фоне служит иллюстрацией и не меняет тему.
- Положение текста задаётся уже в исходнике и сохраняется в недельном манифесте.
  За первые четыре карточки недели используются все четыре зоны: сверху слева,
  сверху по центру, снизу слева и снизу по центру. Раскладка стабильна при повторном
  запуске одной недели, но меняется между неделями.
- У каждой повторяющейся рубрики есть собственный круг формулировок. Соседние
  выпуски одной рубрики не получают одинаковый заголовок; после использования всех
  вариантов круг начинается заново.
- Остальные фотографии берутся из исходной галереи автомобиля без AI-стилизации,
  текста, декоративных элементов и изменения самой сцены.
- Для технической совместимости остальные кадры можно только привести к общей
  форме и формату файла: одинаковые пропорции, допустимая обрезка и преобразование
  в JPEG.
- Порядок публикации всегда один: сначала сгенерированная лицевая карточка, затем
  исходные фотографии.
- Исходная фотография, из которой сделана лицевая карточка, второй раз сразу за
  ней не публикуется. Карусель содержит обложку и только остальные кадры галереи.
- Одна и та же серия в одинаковом порядке отправляется в Instagram, Threads и
  телеграм-канал.
- Генератор запускается один раз на публикацию — только для лицевой карточки, а не
  отдельно для каждого снимка серии.

## Текст публикации

Текст формируется автоматически из свежих данных каталога отдельно от генерации
изображения. Недельный планировщик должен использовать готовые шаблоны рубрик из
`scripts/lib/social-blocks.mjs`, а не только общий шаблон одной машины.

Общие правила:

- машины, фотографии, актуальный статус и исходные данные цены берутся из живого
  production-каталога `abcars.by`, а не из локальной копии базы; если каталог
  недоступен, подготовка недели завершается ошибкой и ничего не публикует;
- проданные и недоступные объявления не участвуют в подборе;
- до появления новых квот в 2027 году цена для соцсетей всегда считается без
  квоты, с полной пошлиной 15% (`quotaOver: true`); состояние переключателя
  «Цены с квотами» на сайте на публикации не влияет;
- у записи об одной машине указываются название, год, цена под ключ в долларах и
  белорусских рублях, пробег и доступные характеристики силовой установки;
- отдельно говорится, что в цену входят доставка, растаможка и сборы;
- номер объявления ставится только в записи об одной машине;
- в подборках, сравнениях, новинках и списке упавших цен номера объявлений не
  ставятся;
- каждая рубрика добавляет свою смысловую строку или вопрос;
- в конце автомобильной записи автоматически добавляется короткий призыв написать
  в Директ, а в Telegram — в личные сообщения;
- для оптимальной машины не показываем сравнение с самой дешёвой и не объясняем,
  сколько нужно доплатить: остаётся только короткая формулировка про сочетание цены
  и состояния;
- текст строится до публикации по правилам рубрики и отправляется вместе со всей
  серией фотографий.

Различия между сетями:

- **Instagram:** без некликабельного адреса, с номером машины, отсылкой к ссылке в
  шапке профиля и тематическими хештегами;
- **Threads:** с прямым адресом карточки, без хештегов;
- **Telegram:** ссылка скрыта под словами «Смотреть в каталоге», хештегов нет;
  призыв ведёт в личные сообщения.
- Если в тексте Threads или Telegram нет никакой ссылки или адреса `abcars.by`, в
  самом низу отдельным абзацем добавляется: «Каталог авто с пробегом из Китая —
  abcars.by». При уже существующей ссылке эта строка не дублируется.

Два поста из `../threads.txt` являются самостоятельными текстовыми публикациями и
не получают автомобильную подпись. Это единственное исключение из правила об
обязательной картинке: никакие другие записи без изображения не публикуются.

## Проверка перед публикацией

Для каждой записи о машине система заново проверяет:

1. объявление ещё активно;
2. фотографии и страница машины доступны;
3. цена не изменилась настолько, что публикация вводит человека в заблуждение;
4. год, пробег и характеристики совпадают с подготовленным текстом;
5. утверждение записи остаётся правдивым: машина всё ещё самая дешёвая,
   оптимальная, новая или входит в заданный бюджет;
6. ссылка и номер ведут на нужную карточку.

Небольшие изменения не блокируют выход. Если проверка выявила существенную
проблему, запись возвращается на подготовку или пропускается; запасная карточка не
подставляется.

## Что готовим заранее

- исходную карточку из фото и оформления;
- один сгенерированный вариант по автоматически назначенному промпту;
- остальные исходные фотографии серии без стилизации;
- номер использованного промпта;
- текстовую заготовку без неподтверждённых текущих данных;
- плановую дату и сети публикации.

Если цена или другие меняющиеся сведения встроены прямо в сгенерированное
изображение, срок такой картинки ограничен одной неделей. Предпочтительный вариант
на будущее: генерировать художественную основу отдельно, а название, цену и другие
динамические данные накладывать обычным способом перед выходом.

## Очередь и статусы

Каждая публикация проходит состояния:

`Новая → Исходник готов → Генерируется → Запланирована → Опубликована`

Дополнительные состояния: `Требует обновления`, `Пропущена`, `Архив`.

Для карточки сохраняем исходник, результат генерации, номер промпта, машину или
тему, дату подготовки, дату последней автоматической проверки и результат
публикации. Ручного утверждения перед выходом нет.

## Работа без API генерации изображений

Генерацию выполняем заранее через еженедельную задачу Codex. Расписание публикаций
не должно вызывать генератор в момент выхода отдельной записи. При этом проверка
собственного каталога, пересчёт текста и техническое наложение актуальных данных
не являются вызовом API генерации изображений и могут выполняться автоматически.

## Связь Codex и сервера

1. Codex готовит недельный манифест командой `npm run social:week:prepare`.
2. Для каждого из пяти исходников Codex применяет назначенный промпт и сохраняет
   результат по адресу `generated.file` из манифеста.
3. Команда `npm run social:week:finalize` проверяет наличие всех пяти результатов,
   переводит их в JPEG и загружает готовый пакет в служебный GitHub Release.
4. Серверный таймер раз в 15 минут запускает `npm run social:week:publish`, берёт
   наступившие слоты и отправляет их в три сети.
5. Перед отправкой сервер проверяет, что выбранные машины всё ещё активны и что
   сгенерированная обложка действительно доступна.

Если сгенерированной обложки нет или она не скачивается, публикация помечается как
`Пропущена`. Сервер не подставляет вместо неё обычную фотографию и не отправляет
текст без картинки. Для временного сбоя API социальной сети сохраняется результат
по каждой сети отдельно, а неудавшаяся отправка повторяется без дублирования уже
опубликованных сетей.

Рабочие времена первого запуска: визуальные записи — с понедельника по пятницу в
13:00 по Минску; вопросы из `threads.txt` — во вторник в 18:30 и в субботу в 12:00.
Они вынесены в `scripts/lib/social-week.mjs` и могут быть изменены без переделки
остального конвейера. Рабочая форма всех кадров — вертикальная 4:5, 1080×1350.

## Пока не решено

- граница изменения цены, после которой карточку нужно остановить;
