Talking to the user: he is not a programmer. He sets the goals and makes the product calls, but
he does not read code and does not know the vocabulary. Work at full depth; explain in plain
words. Say what a change means in practice — what a visitor sees, what breaks, what it costs —
not how it works inside, unless he asks. Keep commit hashes, test names, function and variable
names, code snippets and command output out of the prose (file links are fine, they are
clickable). Give any command he needs to run whole, ready to press. When a choice is his,
describe the options by their consequences and say which one you recommend. He checks the

Vehicle-page rendering policy (2026-08-23): `/cars/:id` is rendered by the server at request time, not shipped as files. `vercel.json` rewrites the route to the API function, `server/car-page.mjs` reads the listing from the database and renders it with `server/seo-render.mjs`, and the response carries a shared CDN cache (`s-maxage=600, stale-while-revalidate=86400`). A missing or sold listing answers **404** with a "listing no longer available" page — the previous behaviour returned 200 for every `/cars/<anything>`, which is 31 000 soft-404s for a search engine. When the database or the shell cannot be reached the handler falls back to `car.html` with a 503/500 status, so the app still boots but the crawler is told to come back later.

The renderer needs an empty page skeleton with this build's hashed asset links: the build writes `dist/client/app-shell.html` for that (an untouched vite shell plus `noindex`, disallowed in robots.txt). `index.html` cannot serve as that skeleton because the generator overwrites it with the home page; the generator therefore also *prefers* `app-shell.html` as its own input, which makes re-running it on an existing `dist/` safe. On the host the function has no `dist/`, so it fetches `app-shell.html` and `car.html` once over HTTPS from `VERCEL_PROJECT_PRODUCTION_URL`/`VERCEL_URL`/`SITE_URL` — never from the request's `Host` header, which is spoofable and would let an attacker supply our page skeleton.
