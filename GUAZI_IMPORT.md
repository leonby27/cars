# Массовый импорт Guazi — скрытый серверный сбор

## Обновление через Telegram — подготовлено 28.09.2026

Регулярный обновлятор `scripts/refresh-guazi.mjs` отделён от завершённого сборщика
`/opt/abcars-guazi-pilot`. Новые команды становятся доступны **после выкладки кода
и перезапуска `abcars-bot`**. Подготовка кода сама по себе не запускает импорт и
не меняет production. Скрипт выкладки перезапускает работающий бот; остановленный
бот не включает. У действующей службы `KillMode=process`, поэтому её перезапуск
не останавливает отделённые процессы обновления.

| Команда | Действие |
| --- | --- |
| `Круг 1` / `Круг` | Прежний полный проход Che168 |
| `Круг 2` | Новый полный проход Guazi, если предыдущий завершён |
| `Статус 2` | Состояние Guazi, текущая марка, числа обновлений и время отчёта |
| `Стоп 2` | Мягкая остановка Guazi с завершением текущих запросов |
| `Продолжить 2` | Оставшиеся проверки того же прохода Guazi |

Команды без номера `статус`, `стоп`, `продолжить` относятся к Che168. Управление
Guazi не останавливает и не перезапускает Che168. Повторный запуск защищён файлом
процесса и блокировкой в PostgreSQL. Бот отвечает на запуск только после появления
живого процесса и его контрольной точки; ошибки запуска идут в отдельный журнал.

Каждый новый круг сохраняет начальный список всех активных Guazi (включая скрытые
межисточниковые дубли), заново считает марки и читает публичную выдачу по обоим
экспортным разделам. Марки идут от малых к большим. Нулевые числа переписи не
отменяют проверку выдачи. Сохраняются действующие фильтры, разделение крупных
выборок и проверки полноты. Аккаунт владельца и закрытые отчёты не используются.
Четыре обработчика делят прежний интервал 750 мс между запросами.

Цена берётся только из FOB USD Horgos. Корректная карточка обновляется через общую
запись каталога; её ID, дата первоначального импорта, полная галерея и прежнее
необязательное китайское обогащение сохраняются. Новые карточки добавляются с
`source=Guazi`. Переключатель видимости источника не изменяется. Shanghai, отсутствие
котировки или неполные характеристики не заменяют прежнюю корректную цену.

**Снятие с продажи (исправление подготовлено 30.09.2026):** достаточно явного
`rawData.displayStatus === 1` в карточке с совпадающим `productId`. Это проверенное
значение «продано»: сам Guazi выбирает по нему панель `VehicleDetails.sold`,
а для `displayStatus === 2` показывает `Under Offer`. Проверка использует уже
полученную карточку, без дополнительных запросов и без изменения темпа импорта.
Старая цена у проданной машины сохраняется в ответе Guazi и не отменяет этот статус.
Существующая машина снимается даже при оставшейся ссылке в выдаче; новая проданная
карточка не добавляется. Сохраняются минимальные доказательства: URL, время,
`productId` и `displayStatus`.

Прежний запасной путь сохраняется: завершённый обход марки, отсутствие ID в нём
и два отдельных ответа 404/410 с обычной страницей Guazi/Next.js. Редирект,
страница защиты, ошибка сети/сервера, скрытая цена, неизвестный статус или пропуск
только в выдаче не снимают машину. Если явного статуса продажи нет, карточка
отвечает 200, но отсутствует в выдаче, её корректная цена обновляется, а наличие
остаётся непроверенным («Нужно проверить»). Историческая марка без доступного
раздела снимается только по явному статусу продажи.

БД.** Без `--run` выводится только справка. Старый завершённый сборщик, локальный
импортёр и очереди фото для этого не перезапускаются. Автоматическое расписание

## Схема

1. `scripts/guazi-census.mjs` считает 172 сегмента (марка × двигатель), отдельно обе части `exportPolicyEligible=1/0`. Складывает числа по родительской марке и сортирует по возрастанию. Это число кандидатов, до ценовых ограничений и удаления дублей.
2. `scripts/guazi-bulk.mjs` на сервере `/opt/abcars-guazi-pilot` обходит страницы последовательно в этом порядке. Четыре обработчика карточек, общий интервал публичных запросов 750 мс. Файлы и контрольные точки сохраняются на сервере.
3. `scripts/guazi-import-local.mjs` получает записи по SSH, проверяет FOB и записывает через общий `upsertCar` только в `127.0.0.1:54329/chinacar`. Другой адрес базы запрещён самой программой. Принятые JSON остаются также локально.
4. `scripts/guazi-photos-local.mjs` независимо сохраняет первые две фотографии каждой машины общей очередью до восьми одновременных загрузок в `runtime/guazi-image-cache`. Все остальные URL галереи сохраняются в карточке; файлы скачиваются при первом открытии через `/api/image`. Это ещё не полная офлайн-копия всех галерей. Фото не задерживают запись карточек.

Только публичные данные: свежая анонимная сессия Chromium на сервере, без профиля/куки аккаунта владельца. Закрытые отчёты и фото дефектов не запрашиваются. Публичные оценки, краткое состояние, параметры и здоровье батареи сохраняются только когда действительно предоставлены. Китайское текстовое описание — необязательное дополнение, его отсутствие не мешает FOB-импорту.

## Отбор и цена

Сегменты и минимальная регистрация соответствуют `GUAZI_FILTERS.md`. Для этого запуска сохранены числовые пределы $7 000–100 000, но они применяются уже к FOB Horgos; это не эквивалент прежней чистой цены машины. Дополнительная общая политика модельного года/итоговой стоимости продолжает действовать.

Bulk явно выбирает `priceBasis: FOB` поверх старой конфигурации изолированного прототипа. Нужна подтверждённая USD-котировка `Horgos, China`. Shanghai не подменяет Хоргос. Нет котировки — `needs_review`, машина не публикуется.

В карточке: `priceBasis=FOB`, `fobPriceUsd`, `fobPort=Horgos`, исходная ссылка и время цены. Совместимое поле `chinaPrice` содержит пересчёт FOB в юани с меткой `chinaPriceBasis=converted_fob`; это не китайская цена автомобиля. Калькулятор использует именно исходный FOB USD. Китайскую доставку и экспортное оформление второй раз не прибавляет. Перевод денег, доставка Хоргос–Минск, сборы в Беларуси и услуги остаются. Растаможка с полного FOB обозначена предварительной до разделения инвойса.

`listings.source=Guazi`, `external_id=productId`, `id=guazi-<productId>`, `source_payload.importRun` отделяют записи от Che168. Повтор запуска обновляет те же ID, не создаёт дубли.

Скрываются выдача, прямые карточки и расчёты по каталогу. Записи не удаляются. Новые вставки не включают источник обратно. Повторное нажатие возвращает машины.

Миграция `038_catalog_sources.sql` создаёт Guazi выключенным по умолчанию. В текущей локальной базе источник включён явно. В рабочую базу миграция не применялась.

## Контроль и продолжение

Локальные файлы в `runtime/guazi-import-20260926/`:

- `local-state.json`, `local-events.jsonl`, `worker.log`, `worker.pid` — запись карточек и события источника;
- `photos-state.json`, `photos-events.jsonl`, `photos.log`, `photos.pid` — очередь первых двух фото;
- `accepted/*.json` — нормализованные публичные записи;
- `monitor-state.json` — какие события уже проверены монитором.

На сервере в одноимённом runtime: `census.json`, `bulk-state.json`, `events.jsonl`, `cards/`, `accepted/`. Секретов входа в этих файлах нет.

Непройденная проверка доступа или ошибка карточки останавливает обход с сохранением прогресса. Повторы/неполнота выдачи проходят ограниченную повторную проверку и подразделение набора; неподтверждённая полнота не объявляется успехом. Ошибка фото останавливает отдельную очередь фото, но карточки продолжают поступать. `rejected` по возрасту/цене — штатный отбор; `needs_review`, `error`, `warning`, `stopped` требуют внимания. Пропажа из выдачи не означает продажу и не меняет старые машины на проданные. Публичная карточка не гарантирует возможность экспорта: признак `sourceExportPolicyEligible` сохраняется отдельно.

Контроль в этой задаче Codex настроен раз в 20 минут: новая проблема, остановка, отсутствие прогресса более пяти минут, завершение. По явному разрешению пользователя монитор диагностирует сбои, исправляет их, проверяет результат и возобновляет процессы самостоятельно; не делает слепые бесконечные перезапуски. Отправка уведомления зависит от работающего приложения и компьютера. Текущий приёмник и фото работают на ноутбуке; сон/потеря сети остановят поступление в локальную базу. Это не полностью серверная промышленная установка.

Возобновление из корня `abcars` после устранения причины:

```sh
node scripts/guazi-import-local.mjs guazi-import-20260926
node scripts/guazi-photos-local.mjs guazi-import-20260926
```

Запускать в отдельных процессах. Проверить PID из соответствующего lock-файла и его команду; никогда не удалять блокировку живого процесса. После аварии допустимо удалить только подтверждённо устаревший `local.lock`, `photos.lock` или серверный `bulk.lock`. Перед остановкой определить текущего SSH-потомка локального приёмника, завершить его, дождаться приёмника; если остался буфер событий, он может ещё обрабатываться. Принятые записи повторно передаются с серверных контрольных точек при следующем запуске, локальный список `received` предотвращает повторную запись.

`warmPhotoBatch` наполняет общий пул из нескольких машин, ограничивает одновременно исполняемые загрузки восемью и не ждёт завершения медленной машины для начала следующей. Запись состояния сериализована, чтобы параллельные завершения не сталкивались на временном файле. Машина отмечается готовой только после всех выбранных фото. При постоянной ошибке новые запросы прекращаются, уже начатые завершаются; незавершённые машины остаются в очереди. Сохранены повторы временных сетевых ошибок, порог свободного диска 5 ГБ и мягкая остановка.

В каталоге Guazi предварительная браузерная подгрузка при приближении карточки к экрану тоже ограничена первыми двумя. Остальные кадры доступны при наведении/пролистывании или открытии галереи. Любое изображение Guazi идёт через `/api/image`: если локальной копии нет, наш API скачивает её из разрешённого CDN, проверяет формат, сохраняет в `runtime/guazi-image-cache` и отдаёт посетителю; последующие обращения используют сохранённую копию. Полный список ссылок в карточке не сокращён, поведение Che168 не менялось.

Проверки: 1038 тестов и клиентская сборка прошли, без визуальной проверки. Тест пула удерживает медленное фото одной машины и подтверждает завершение другой при соблюдении общего лимита; третье и последующие фото заранее не запрашиваются. Проверены завершение активных запросов перед выходом на ошибке и продолжение очереди. HTTP-проверка третьего фото `hgslwkclr2`: до запроса кеш отсутствовал, `/api/image` вернул 200 и сохранил 262181 байт; последующее чтение подтвердило совпадающую собственную копию.

Фото-процесс обновлён до PID 11851, импортёр не перезапускался. Первый короткий замер: 125 машин за 55 секунд (~137/мин против прежних ~9/мин с пятью фото). Это результат совместного уменьшения числа фото и параллельной очереди, а не гарантированный темп для всего остатка; контроль через 20 минут сохраняется.

## Восстановление доступа к спискам, 26.09.2026

В 19:27 UTC импорт остановился на XPeng, 9791 принятая карточка. API списка вернул HTTP 200 с не-JSON содержимым и был классифицирован как `SOURCE_BLOCKED`. Тело того ответа не сохранено, поэтому точный вид проверки задним числом не установлен. По коду и журналу причина отсутствия восстановления ясна: механизм общей браузерной актуализации сеанса был подключён только к чтению карточек, а `publicSearch` сразу выбрасывал ошибку без попытки обновить каталог.

Теперь `publicSearch` использует ту же общую блокировку обновления и тот же браузерный контекст. После отказа открывает обычный публичный каталог, при необходимости выполняет одну разрешённую попытку знакомого checkbox с прежним общим лимитом (4/час, не чаще раза в минуту), повторно получает анонимные did/guid из штатного запроса страницы и один раз повторяет исходный запрос списка. Фильтры, страница и recommendId сохраняются. Другие работники ждут завершения обновления; новый браузер/IP/аккаунт не подключается. При ограничении частоты учитывается Retry-After и общий темп снижается, как для карточек.

Второй отказ после обновления останавливает сбор. HTTP 401 и ошибки структуры JSON не запускают такое восстановление. Ответы API освобождаются во всех ветвях; идентификаторы посетителя не пишутся в журнал. Существующие разделы discovery и сохранённые карточки повторно используются.

1040 тестов прошли, включая обновление анонимного контекста списка без изменения запроса, один повтор, остановку при повторной проверке, отказ от восстановления при 401/невалидной структуре и освобождение ответов. Исправленный модуль установлен только в изолированный сборщик, SHA-256 проверен. Локальный импортёр возобновлён PID 12884; фото-процесс PID 11851 продолжает работать без перезапуска.

В 19:51 UTC возобновлённый обход прошёл прежнюю страницу остановки, завершил discovery этой части XPeng и начал запись новых карточек (9812+ всего). Это подтверждает продолжение; автоматическое восстановление именно следующей живой проверки списка ещё предстоит наблюдать. Скорость фото подтверждена на 20 минутах: 4284 машины (~214/мин), один сетевой тайм-аут повторён успешно, остановки очереди не было.

## Межисточниковые дубли, 28.09.2026

Guazi и Che168 иногда публикуют одну физическую машину под разными ID. Карточки не удаляются и не объединяются в таблицах источников. Отдельная таблица `catalog_duplicate_matches` хранит только обратимую связь «вторичная → основная», а публичное представление `catalog_listings` скрывает Guazi, пока связанная карточка Che168 активна. Если Che168 станет недоступна или её источник будет выключен, Guazi автоматически вернётся в каталог.

Автоматическая связь требует совпадения марки, модели, модельного года, месяца первой регистрации, нормализованного города, цвета, типа силовой установки и привода. Допускается разница пробега не более 500 км, цены — не более 8% или 8000 CNY, батареи — 0,5 кВт·ч, запаса хода — 5 км. Пустые цвет, город или регистрация исключают автоматическое решение. Совпадение принимается только взаимно-однозначно: ровно один Che168 для Guazi и ровно один Guazi для Che168. Неоднозначные случаи остаются видимыми.

`npm run dedupe:catalog` выполняет безопасный предварительный расчёт, `npm run dedupe:catalog -- --apply` синхронизирует связи. На сервере это делает `abcars-catalog-dedupe.timer` каждый час; выкладка также выполняет сверку сразу после миграций. Карта сайта, IndexNow и фид Яндекса читают то же публичное представление и не публикуют скрытые дубли.
