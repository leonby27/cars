## Устройство

`publicGuaziPreviewSource` в `scripts/lib/guazi-preview-card.mjs` формирует снимок по разрешённым публичным полям и вообще не обращается к `inspection.full`. Адаптер работает без полного отчёта и его фото. При отсутствии публичной оценки или текста не использует закрытые данные как запасной вариант.

Vite-плагин `scripts/vite-guazi-preview.mjs` работает только при `serve`. Маршрут карточки возвращает только публичные сведения; фотомаршрут разрешает только файлы текущей галереи. Старые фото осмотра могут оставаться на диске, но через этот маршрут не отдаются. Исходный расширенный сбор сохранён отдельно в `runtime/guazi-enrichment-work/`; его удаление не требовалось.

`GUAZI_PREVIEW_ENABLED`: локально включено, в production выключено. Данные в `runtime/local-guazi-preview/` игнорируются Git и не входят в сборку. База и основной каталог не меняются, добавление этой машины в избранное отключено. Кнопка заявки остаётся на месте для проверки интерфейса, но вместо отправки открывает уведомление о режиме предпросмотра. Серверный массовый сборщик и его профили этим изменением не перенастраиваются.

## Подготовка

```sh
node scripts/prepare-guazi-local-preview.mjs runtime/guazi-enrichment-work/sample-enriched-card.json
```

Скрипт сохраняет только публичную проекцию снимка и готовит только 27 файлов галереи. Уже сохранённые снимки повторно используются после проверки SHA-256. Полный отчёт, аккаунт и файл сеанса не требуются.

Проверки: адаптер не читает полный отчёт (проверено в том числе с запрещающим доступ свойством), сохраняет публичные оценки и не подставляет закрытые сведения. HTTP и серверное формирование разметки проверяют отсутствие полного отчёта, счётчиков и старых фото осмотра. Визуальная проверка не выполняется по правилам проекта.
